# Havchik — концепт приложения

> Статус: **черновик концепта на утверждение**. Код ещё не писался.
> Назначение: закрытый круг друзей/коллег в офисе. Публичной регистрации нет.

---

## 1. Что это

Веб-приложение (PWA) для офиса: собрать в один список «кто что хочет пожрать»,
когда заказываем еду из привычных мест.

Три базовых сущности:

1. **Места** (`מקומות` / «places») — рестораны/доставки, откуда обычно заказываем, со своим меню.
2. **Голосование** (опционально) — куда заказываем сегодня.
3. **Сессия заказа** — открытая «шапка» заказа из конкретного места; каждый заходит и добавляет свои позиции.
4. **Итоговый документ** — сводный список: имя, блюдо, добавки, особые пожелания. Печать / PDF / WhatsApp / копировать.

---

## 2. Стек

| Слой | Решение | Почему |
|---|---|---|
| Frontend | React 19 + TypeScript + Vite | быстрый dev, статическая сборка |
| UI | Tailwind CSS + собственные компоненты | полный контроль над RTL |
| Backend | **Firebase**: Firestore (данные), Auth (вход), Hosting (раздача), опционально Cloud Functions | без сервера, бесплатный tier покрывает 10–20 человек с запасом |
| Realtime | Firestore `onSnapshot` | список заказа обновляется у всех мгновенно, без F5 |
| Экспорт | печать через CSS `@media print` → PDF браузером; текстовый экспорт → WhatsApp / копировать; CSV | ноль внешних зависимостей |
| Офлайн | Firestore offline persistence + PWA manifest + service worker | «добавить на главный экран», работает в лифте |

Cloud Functions на старте **не нужны** — всё закрывается правилами безопасности Firestore.
Платный план Blaze не требуется.

## 3. Доступ и приватность

Это частный круг, поэтому:

- Вход через **Google Sign-In** (один тап на телефоне) + опция **анонимного входа по коду-приглашению**.
- Коллекция `members` — белый список. Кто не в списке — видит экран «запроси доступ», данных не получает (это enforced в Security Rules, не только в UI).
- Первый вошедший становится `admin`. Админ может: добавить/удалить участника, выдать роль, удалить место/сессию.
- Приглашение: ссылка + 6-символьный код. Код проверяется правилами, одноразовость не нужна в таком масштабе.
- Никаких платежей, телефонов, адресов — только имя/ник и аватар.

**Роли:**

| Роль | Права |
|---|---|
| `member` | создавать места, редактировать меню, открывать сессию заказа, свои позиции, голосовать |
| `admin` | всё выше + управление участниками + удаление чужого/архивация |

Сознательное решение: редактирование меню доступно **всем** участникам (как просил заказчик), история правок пишется в `menuItems.updatedBy` — чтобы было видно, кто что сломал.

## 4. Языки

- Дефолт: **עברית (he)**, направление **RTL**.
- Второй язык: **русский (ru)**, LTR.
- Переключатель в хедере, выбор в `localStorage` + в профиле пользователя.
- Реализация: свой лёгкий словарь `src/i18n/{he,ru}.ts` + хук `useT()`. Без i18next — лишние 40 КБ ни к чему.
- RTL: `dir` на `<html>`, Tailwind logical properties (`ps-`/`pe-`/`ms-`/`me-`), иконки-стрелки зеркалятся.
- **Контент (названия мест и блюд) не переводится** — пишется как есть, обычно иврит, иногда русский. Поиск по меню нечувствителен к регистру и к ивритским огласовкам (ניקוד убирается перед сравнением).
- Итоговый документ печатается на языке интерфейса того, кто печатает; названия блюд — в оригинале.

## 5. Модель данных (Firestore)

```
members/{uid}
  displayName, photoURL, role: 'admin'|'member', lang: 'he'|'ru', createdAt

places/{placeId}
  name, nameNote?            // «Pizza Shmil, тот что на углу»
  phone?, url?, address?
  tags: string[]             // пицца, хумус, суши
  deliveryFee?, minOrder?, notes?
  isArchived: bool
  createdBy, createdAt, updatedBy, updatedAt

places/{placeId}/menuItems/{itemId}
  name, description?
  price?                     // число, ILS; null = «цена по ситуации»
  category?                  // «מנות עיקריות», «שתייה»
  options: [                 // настраиваемые добавки
    { id, label, type: 'single'|'multi', required: bool,
      choices: [{ id, label, priceDelta }] }
  ]
  isAvailable: bool
  sortOrder, createdBy, updatedBy, updatedAt

polls/{pollId}               // голосование — НЕ обязательный шаг
  title, status: 'open'|'closed'
  candidatePlaceIds: string[]
  allowMultiple: bool, allowAddOptions: bool
  deadline?: timestamp
  createdBy, createdAt
  votes/{uid} -> { placeIds: string[], votedAt }
  // результат считается на клиенте; победитель можно одним тапом
  // превратить в сессию заказа

orders/{orderId}             // сессия заказа
  placeId, placeNameSnapshot // снимок имени — если место переименуют, старый заказ не поедет
  title?                     // «Обед пятница» — по умолчанию дата
  status: 'open'|'locked'|'done'
  deadline?: timestamp
  fromPollId?
  createdBy, createdAt, lockedAt?
  notes?                     // «скидываем по 50, кто не успел — сам»

orders/{orderId}/items/{itemId}
  userId, userNameSnapshot
  menuItemId?                // null, если написано своими словами
  nameSnapshot               // всегда заполнено
  freeText?                  // «что-то без лука, удиви меня»
  selectedOptions: [{ optionLabel, choiceLabels: string[], priceDelta }]
  specialRequest?            // особые пожелания
  qty: number
  priceEstimate?             // price + сумма priceDelta, * qty
  createdAt, updatedAt
```

### Правила безопасности (суть)

- Читать что-либо может только uid, присутствующий в `members`.
- `orders/*/items/*`: создавать/править/удалять — только `request.auth.uid == resource.data.userId`, и только пока `orders.status == 'open'`. Админ и автор сессии — могут править любые позиции (чтобы поправить чужую опечатку перед звонком в ресторан).
- `places`, `menuItems`: пишет любой `member`, удаляет — автор или админ.
- `polls/*/votes/{uid}`: пишет только сам `{uid}`, и только пока `status == 'open'`.
- `members`: пишет только `admin`; свой `lang`/`displayName` может менять сам пользователь.

## 6. Экраны

### 6.1 Главная
- Если есть открытая сессия заказа — большая карточка сверху: место, дедлайн, сколько человек уже заказали, кнопка **«Добавить свой заказ»**.
- Если есть открытое голосование — карточка голосования.
- Иначе — две кнопки: **«Открыть заказ»** / **«Запустить голосование»**.
- Ниже: последние 5 закрытых заказов (быстрое «повторить как в прошлый раз»).

### 6.2 Места
- Список карточек с тегами и поиском.
- Карточка места → меню по категориям, цены, редактирование inline.
- **«Создать место»**: имя + теги — минимум два поля, остальное потом.
- Редактор меню: быстрый ввод «одна позиция = одна строка», добавки — опционально, свёрнуто (чтобы не отпугивать). Массовая вставка: вставил текст меню из WhatsApp — распарсилось в строки «название — цена», дальше правишь.

### 6.3 Голосование
- Выбираешь места-кандидаты из списка (или пишешь новое).
- Один/несколько голосов, опциональный дедлайн.
- Live-результаты: полосы, кто за что (не анонимно — в кругу друзей это фича: видно, кого уговаривать).
- Кнопка **«Заказываем отсюда»** → создаёт сессию заказа из победителя.
- **Голосование можно полностью пропустить** — любой участник открывает сессию заказа напрямую.

### 6.4 Сессия заказа
- Шапка: место, дедлайн, статус, счётчик участников, кнопки «Итог», «Закрыть приём».
- Моя часть: мои позиции с ценами, кнопка **«Добавить»**.
- Добавление позиции:
  - поиск по меню → тап по блюду → добавки (чекбоксы/радио) → особые пожелания → кол-во;
  - либо таб **«Своими словами»** — просто текст, если в меню этого нет.
- Ниже: список всех участников и их позиции (все всё видят, так меньше дублей и споров).
- Live: позиции появляются у всех сразу.

### 6.5 Итоговый документ — ключевой экран
Отдельная чистая страница (`/order/:id/summary`), пригодная для печати и отправки.

```
הזמנה — Pizza Shmil                     04.11.2026
──────────────────────────────────────────────────
Дима      פיצה משפחתית     без лука, доп. сыр    68 ₪
          קולה זירו                              10 ₪
Саша      שווארמה בלאפה    חריף, бэз תחמוצת      55 ₪
Миша      «что-то вегетарианское, доверяю»        —
──────────────────────────────────────────────────
Всего позиций: 4 · Участников: 3 · Сумма ≈ 133 ₪
Доставка 15 ₪ · Итого ≈ 148 ₪
```

Два режима отображения, переключаются одним тапом:
- **По людям** (главный) — кто что заказал. Для расчёта кто сколько скидывает.
- **По блюдам** (агрегат) — «פיצה משפחתית ×2, קולה ×3». Для диктовки по телефону в ресторан.

Действия:
- **Печать** — `window.print()`, отдельный print-стилевой лист (A4, без интерфейса, чёрно-белый).
- **PDF** — та же печать → «Сохранить как PDF» (браузерное, 0 зависимостей). Если понадобится «честный» PDF — добавим позже.
- **WhatsApp** — `https://wa.me/?text=...` с текстовой версией; плюс кнопка **«Копировать текст»**.
- **Поделиться** — Web Share API на телефоне (нативное меню).
- **CSV** — для тех, кто ведёт учёт в таблице.
- **Ссылка** — любой участник открывает тот же итог у себя.

## 7. Что сознательно НЕ делаем в v1

- Оплата, расчёт долгов, интеграция с Bit/Paybox.
- Фото блюд (хранилище, модерация, вес) — только текст и цена.
- Публичная регистрация, email-подтверждения.
- Push-уведомления (вместо них — ссылка в WhatsApp-группу, она и так есть).
- Админ-панель как отдельное приложение.
