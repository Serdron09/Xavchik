# Havchik / חבצ׳יק

Приложение для офиса: собрать в один список, кто что хочет заказать поесть.
Закрытый круг, вход по коду приглашения. Иврит (RTL) по умолчанию, русский вторым.

Концепт и обоснование решений: [`CONCEPT.md`](./CONCEPT.md).

## Что умеет

- **Места** со своим меню. Создавать и править меню может любой участник; `updatedBy` помнит, кто правил.
- **Добавки** у блюда: группы «один из» / «несколько», с доплатой.
- **Вставка меню списком** — одна строка на позицию, `название - цена` разбирается автоматически.
- **Голосование** (необязательный шаг): места-кандидаты, один или несколько голосов, живые результаты, «заказываем у лидера» одним тапом.
- **Сессия заказа**: любой участник открывает, остальные добавляют позиции из меню или своими словами, с особыми пожеланиями. Обновляется у всех в реальном времени.
- **Итоговый документ**: режим «по людям» (кто сколько скидывает) и «по блюдам» (диктовать по телефону). Печать/PDF, WhatsApp, копировать текст, системное «поделиться», CSV.
- Офлайн-кэш Firestore, PWA — можно добавить на главный экран.

## Стек

React 19 + TypeScript + Vite, Tailwind CSS 4, Firebase (Auth + Firestore + Hosting).
Cloud Functions не используются, план Blaze не нужен.

## Настройка Firebase (один раз)

1. **Authentication → Sign-in method**: включить **Google** и **Anonymous**.
2. **Firestore Database**: создать базу (режим production — правила в репозитории всё закрывают).
3. **Создать документ с кодом приглашения** вручную, в Firestore:

   Коллекция `config`, ID документа `invite`, поля:

   | Поле | Тип | Значение |
   |---|---|---|
   | `code` | string | код приглашения, например `HAVCHIK` (заглавными) |
   | `adminClaimed` | boolean | `false` |

   Без этого документа никто не сможет присоединиться — это и есть «белый список на входе».
   Первый, кто войдёт и введёт код, автоматически станет админом, а `adminClaimed`
   переключится в `true`. Дальше все входят обычными участниками, админ может
   повысить любого на странице «Участники».

4. **Authentication → Settings → Authorized domains**: добавить домен, с которого
   открываете приложение (для `firebase deploy` домен проекта уже в списке).

Код приглашения меняется там же, в `config/invite.code`. Он виден админам на
странице «Участники».

## Запуск локально

```bash
npm install
```

```bash
npm run dev
```

Конфиг Firebase уже вшит в `src/lib/firebase.ts` (web-конфиг публичен по дизайну,
доступ закрыт правилами `firestore.rules`). Чтобы указать на другой проект —
скопируйте `.env.example` в `.env` и заполните переменные.

## Деплой

```bash
npm install -g firebase-tools
```

```bash
firebase login
```

```bash
npm run build && firebase deploy
```

Первый деплой заодно загрузит правила и индексы Firestore. Только правила:

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

## Роли и права

| | участник | админ |
|---|---|---|
| Создавать места, править меню | да | да |
| Открывать заказ, голосование | да | да |
| Править свои позиции в заказе | да | да |
| Править чужие позиции | только автор заказа | да |
| Закрывать/удалять заказ, голосование | только свои | да |
| Управлять участниками, видеть код | нет | да |

Все ограничения продублированы в `firestore.rules` — UI не единственная защита.

## Структура

```
src/
  lib/        firebase, типы, форматирование, текст итогового документа
  i18n/       словари he/ru + провайдер (RTL переключается на <html>)
  auth/       вход, присоединение по коду, роли
  data/       запросы и мутации Firestore, live-хуки
  components/ UI-кит, редактор меню, добавление позиции в заказ
  pages/      Home, Places, PlaceDetail, Polls, PollDetail, OrderSession, OrderSummary, Members
firestore.rules      правила доступа
firestore.indexes.json  составные индексы
```
